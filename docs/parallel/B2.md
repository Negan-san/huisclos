## Fait

- PDF : contrôle indépendant de chaque page, sans moyenne globale ni OCR. Une
  page douteuse n'est pas automatiquement qualifiée de scan. Le texte disponible
  reste importable ; une extraction entièrement vide conserve le refus historique.
- DOCX : ordre XML paragraphes/tableaux préservé dans le corps, les cellules
  imbriquées et les en-têtes/pieds. Cellules fusionnées lues une fois. Variantes
  première page et pages paires conservées, puis définitions distinctes ajoutées
  après le corps, sans prétendre reconstituer la pagination Word.
- Limites DOCX signalées : notes, commentaires, zones de texte, révisions et
  contenus intégrés/contrôles de contenu. Les XML du ZIP sont inspectés localement ;
  aucune relation externe n'est suivie et aucune pièce liée n'est ouverte.
- Interface : avertissements traduits EN/FR, pages explicites, explication de la
  différence entre document incomplet et contenu de la requête IA. En cas de

## Contrat de lecture pour A3

`ReadResult(text, source_type, warnings, char_count)` reste constructible avec les
quatre arguments historiques. Un cinquième champ facultatif `quality` contient
un `ReadQuality` immuable, importable depuis `huisclos.io.read_quality` :

| Champ | Valeur et signification |
| --- | --- |
| `status` | `complete`, `partial` ou `unknown` ; défaut historique : `unknown`. |
| `empty_pages` | Tuple d'entiers, numéros PDF commençant à 1, zéro caractère utile extrait. |
| `short_pages` | Tuple d'entiers PDF, de 1 à 19 caractères utiles extraits. |
| `unsupported_structures` | Tuple de catégories DOCX, triées et uniques. |

Un caractère utile est imprimable et n'est pas un blanc. Le seuil de vingt
caractères est seulement un signal de relecture ; il ne prouve ni scan ni perte.
Les listes vide/courte sont disjointes. Les pages sont jointes par deux LF comme
avant ; une page sans texte garde donc sa place dans la séparation des pages.

`complete` porte sur les seuls octets TXT décodés ou le texte collé, après la
normalisation habituelle. Cela ne valide pas un document original non fourni, ni
l'exactitude d'un décodage Windows-1252. Un PDF a toujours `status=unknown`, même
si toutes ses pages dépassent le seuil. Un DOCX sans structure repérée a aussi
`unknown` : absence d'alerte ne signifie pas extraction intégrale. Un DOCX dont
une structure non couverte est repérée a `partial` ; la restitution des révisions
ou contrôles de contenu peut être partielle plutôt que totalement absente.

Les avertissements restent un `tuple[str, ...]`, sans extrait utilisateur :

| Code | Condition et action |
| --- | --- |
| `encoding_cp1252` | Inchangé : relire les accents. |
| `pdf_empty_pages:2,4` | Pages sans texte utile ; vérifier les pages originales 2 et 4. |
| `pdf_short_pages:3` | Page courte ; vérifier l'original, sans conclure à un scan. |
| `docx_notes` | Notes de bas de page ou de fin ; copier les passages utiles. |
| `docx_comments` | Commentaires ; relire et copier les passages utiles. |
| `docx_text_boxes` | Zones de texte ; copier les passages utiles. |
| `docx_revisions` | Révisions ; accepter/rejeter dans une copie puis réimporter. |
| `docx_embedded_content` | `altChunk`, objets ou contrôles de contenu ; vérifier l'original. |

`warning_parameters(code)` sépare le nom et les pages pour `t()`. Seuls des entiers
ASCII positifs sont admis comme paramètres de page. Ne pas traduire directement
un code avec suffixe : appeler cette fonction comme le fait Import.
`ReadQuality.warning_codes()` produit ces codes dans un ordre stable.

`DocumentReadError(code)` et `str(error)==code` restent valables. L'erreur possède
aussi `quality` et `warnings`. Pour un PDF entièrement sans texte, `code` reste
`pdf_no_text` et les pages sont dans `quality.empty_pages`. Pour un DOCX dont le
seul contenu est omis, `code` reste `empty`, mais les alertes DOCX restent disponibles.
Les erreurs de format/chiffrement/taille et les limites antérieures sont conservées.
Une erreur d'extraction PDF invalide toujours tout l'import, sans exposer son texte.

Import garde seulement les codes dans `KEY_READ_WARNINGS`, sans changer state.py.
Les métadonnées structurées sont disponibles au lecteur pour une intégration
ultérieure. Les alertes ne font pas partie du texte détecté, des exports ou de la
requête. Seule l'extraction affichée entre dans le pipeline ; du texte non extrait
affecte la complétude du document, sans fuite automatique de ce contenu dans le
payload. Un passage ajouté doit être relu et pseudonymisé avant envoi.

## Dev anglais : contrat et conventions

`corpus/english_dev/manifest.json` porte `dataset_id=english_dev_v1`, `language=en`
et `split=dev`. Les lignes de `corpus/english_dev/dev.jsonl` gardent exactement les
six champs existants : `id`, `doc_type`, `split`, `title`, `text`, `entities`.
Les métadonnées de langue restent dans le manifeste : le chargeur actuel refuse
les champs JSONL supplémentaires. Test de compatibilité effectué avec
`load_corpus` sur une copie temporaire de ce seul dev anglais.

Genres : employment_correspondence, commercial_agreement, case_memorandum,
management_minutes. Offsets Python Unicode, début inclus et fin exclue, texte
exact, aucune imbrication ni superposition. Civilités et libellés hors span,
formes juridiques accolées incluses, adresses US/UK/FR entières avec unités,
ville, état/code postal et retours à la ligne. Chaque répétition sensible est
annotée, y compris les noms courts. Les références publiques aux textes de loi,
institutions, dates ordinaires et montants restent visibles.

Formats annotés : téléphones US domestiques/+1, UK domestiques/+44 et français
+33 ; dates de naissance numériques et en toutes lettres ; dossiers privés de
style US civil, UK alphanumérique et RG français. Les seuls formats de sécurité
sociale/bancaires annotés sont le NIR et l'IBAN français, avec SIREN/SIRET français
et deux identifiants internes CUSTOM. Aucun type SSN/NIN étranger ajouté.
Les formats présents ne prouvent pas leur prise en charge par les détecteurs.

`build_dataset(mapping_de_sources)` renvoie deux chaînes sans I/O ni détection.
La commande `PY scripts/build_english_dev.py` lit et écrit uniquement dans le
sous-dossier anglais. `--check` ne fait aucune écriture et compare les octets
reconstruits. Le constructeur refuse balises invalides, types inconnus, spans
incorrects, répétitions connues non annotées, domaines non example.com/org,
sources manquantes, identifiants incohérents, volumes ou genres incorrects.
Il ne peut prouver l'exhaustivité sémantique des annotations d'un auteur unique.

Le dev anglais sert au réglage avant gel, jamais à une validation aveugle.
Aucune fixture A2 n'a été consultée pour l'écrire. B3 pourra le charger après
fusion, avec la langue explicite issue du manifeste et les règles de la piste A.
Le dev français et les fichiers/sources test/challenge sont inchangés par B2.
